Security

What Aegis covers, and what it doesn't.

Aegis is one layer. It decides what a tool call may do, refuses anything outside that, and records the decision so it holds up in an investigation. Below, it's mapped category by category against the OWASP MCP Top 10 (2025 working draft). If you're evaluating Aegis, read the "not covered" entries first.

OWASP MCP Top 10

Category by category

Full mapping with evidence
MCP01Token Mismanagement & Secret ExposurePARTIAL›

The risk: hard-coded credentials, long-lived tokens, and secrets left in model memory or logs, which attackers retrieve through injection.

What Aegis does: response inspection scans tool responses for private keys, AWS keys, Luhn-valid card numbers and SSN-shaped values before they reach the model. It can block or warn. Tool content is redacted in every audit field, so the log can't leak.

What it doesn't do: inspection is off by default. It doesn't manage, rotate or vault credentials. Use a secret manager for that.

MCP02Privilege Escalation via Scope CreepCOVERED›

This is the category Aegis was built for. Every call is checked against a frozen, per-task spec that lists exact (server, tool, argument, value) combinations, and anything unlisted is denied at every level. The spec can't widen during a run, and a new spec is generated for each task, so permissions don't build up over time.

Waivers (allow_any, weak posture) carry their own rule ids, so a policy that has drifted wider can be found with a query.

MCP03Tool PoisoningPARTIAL›

What Aegis does: a poisoned tool description can't widen what the tool accepts. Tool metadata isn't an input to policy, and the spec is frozen before the run starts.

Caveat: server fingerprinting exists in aegis/fingerprint.py, but it isn't wired into the enforcement path yet, so you can't rely on drift detection. Wiring it in is on the roadmap.

MCP04Software Supply Chain Attacks & Dependency TamperingNOT COVERED›

Aegis works at runtime, on tool calls. It has no view of how a server or framework was built or what it depends on. Use dependency pinning, SBOMs, artifact signing and provenance checks for this.

MCP05Command Injection & ExecutionPARTIAL›

What Aegis does: where a tool takes a command, path or query and the spec lists the allowed values, an injected value is refused before anything runs. Injected extra parameters are denied too (rule 6). Exact string matching means encoding tricks and traversal sequences can't turn into an allowed value.

What it doesn't do: it doesn't parse or sanitise command strings. If a spec leaves a command argument unconstrained, whatever is in that string runs.

MCP06Intent Flow SubversionCOVERED›

Framing caveat: Aegis doesn't detect prompt injection. It makes a successful injection unable to cause an out-of-scope action. The spec comes from the trusted request before any untrusted text is read, and nothing in the enforcement path treats tool output as instructions.

An injection can still make the agent misuse capabilities the spec did grant, within that scope. Tight specs keep that scope small.

MCP07Insufficient Authentication & AuthorizationPARTIAL›

What Aegis does: authorization at the argument level, finer than OAuth scopes reach. OAuth 2.1 with resource indicators decides which tools an agent may call. Aegis decides which arguments they may be called with. Intercepts add human approval for sensitive pairs.

What it doesn't do: authentication. It assumes an identity layer upstream.

MCP08Lack of Audit and TelemetryCOVERED›

Every decision writes a record before the outcome goes back to the agent. Records carry run_id for correlation, spec_hash to show which policy decided, and rule ids that make waivers visible. Records are exported as OTLP spans and can be collected centrally in the control plane, where gaps in shipping are counted rather than hidden.

Limitation: the log is append-only by convention, not cryptographically immutable. If you need tamper-evidence, ship records to a WORM store.

MCP09Shadow MCP ServersNOT COVERED›

Aegis governs the agents it's wired into. It can't discover servers your organisation doesn't know about. The audit trail lists the known servers in use, which helps you check against an approved list, but that isn't discovery. Use network scanning, egress monitoring and registry enforcement for this.

MCP10Context Injection & Over-SharingPARTIAL›

What Aegis does: it limits what enters the context in the first place. A per-task spec means the agent can read only what its current task allows. Response inspection can add a second check on credential-shaped content.

What it doesn't do: isolate data inside a shared or persistent context window.

Threat model

What's trusted, and what isn't

TRUSTED
  • The user's original request
  • Operator configuration: sandbox_root, intercept rules, callbacks
  • Specs an operator wrote and loaded from disk
  • The Aegis library code and its host process
UNTRUSTED
  • Every tool response: file contents, web pages, API results
  • Every argument the agent produces, including names and values
  • Tool names, descriptions and schemas advertised by MCP servers
  • The model's reasoning, once it has read anything untrusted

Known limitations

In-scope misuse
An injection can still steer the agent within the scope the spec granted. Aegis limits the blast radius. It doesn't make the model trustworthy.
Unconstrained scalars
An argument written as arg: ~ accepts any scalar value. That's useful for content fields, but dangerous for paths or commands.
Fingerprinting not wired in
Server drift detection exists, but enforcement doesn't call it yet.
No tamper-evidence
The audit log has no hash chain yet. Someone with write access to the log could alter it without detection.
Same-process trust
Aegis runs inside the agent's process. Code that can change that process can bypass the wrapper.

Responsible disclosure

Found a way around it?

That's the most useful thing you could send. Please report suspected bypasses or vulnerabilities privately by email, not in a public issue, so a fix can ship first. Include a spec, a call, and the verdict you expected compared with the one you got. The playground makes it easy to build a minimal reproduction.

Every confirmed finding gets a regression test, and the write-up credits you if you'd like that. Two bypasses found so far are described in Your agent's permissions are tighter than your policy thinks and filed with the OWASP MCP Top 10 project.
